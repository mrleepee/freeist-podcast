Every large technology vendor is currently racing to own the exact layer of curated knowledge that your AI agents read before they take action. On June twelfth, twenty twenty-six, Google Cloud made a sharp pivot in a different direction. Researchers Sam McVeety and Amir Hormati announced version zero point one of the Open Knowledge Format. The thesis is precise. What artificial intelligence agents are missing is not another knowledge service. It is a format.

Every single team building autonomous agents rediscovers the exact same problem. You need a place to store the curated facts, metric definitions, operational runbooks, and application programming interface descriptions that an agent has to know to be useful in a specific domain. Right now, that knowledge gets trapped in proprietary workspace documents, bespoke internal databases, or hardcoded prompts. Each of those solutions is locked to one vendor. When you switch models, change cloud providers, or adopt new tooling, your accumulated knowledge does not come with you. The Open Knowledge Format bets that the fix is a standard format, not a standard platform.

A bundle in this format is simply a directory of markdown files. Each file represents one concept. That concept might be a data table, a dataset, a metric, a playbook, or an application programming interface. The file path acts as the concept's identity. A small block of configuration data sits at the top of the file, and only one field is mandated. That field is the type. Everything else, including the title, description, and tags, is optional. The rest of the file is just ordinary markdown text.

These concepts link to one another using standard markdown links. This transforms a flat directory into a rich graph of interconnected knowledge. Two filenames are reserved by convention. An optional index file provides a summary entry point. An optional log file tracks the change history.

The specification is built on three deliberate principles. First, it is minimally opinionated. Mandating only the type field keeps the barrier to producing a bundle as low as writing a basic text document. Second, it enforces producer and consumer independence. The format acts as the contract. A bundle can be hand-authored by a person, exported by a data pipeline, or synthesized by a large language model. All three interoperate perfectly because they produce the exact same file shape. The tooling is entirely swappable on both sides. Third, it relies on format, not platform. There is no cloud lock-in, software development kit requirement, or model mandate. The value comes from how many parties speak the format, not from who owns the registry.

The specification explicitly cites Andrej Karpathy and his large language model wiki concept. Karpathy argues that the tedious bookkeeping defeating human-maintained wikis is exactly the work large language models do well. Updating cross-references, keeping entries consistent, and touching many files at once is difficult for humans. Language models do not get bored. They do not forget to fix a stale link. They can edit fifteen files in a single pass. The Open Knowledge Format is, in effect, a file format designed for an artificial intelligence curator rather than a human one.

This is not just a paper specification. It ships with working tooling. An enrichment agent walks a dataset and drafts concepts with citations and schemas. A static visualizer renders the knowledge graph. Three sample bundles cover electronic commerce, developer forums, and Bitcoin. The Google Cloud Knowledge Catalog product now ingests this format directly.

This development sits next to a real family of conventions converging on the exact same idea. Agent instruction files, linked markdown workspaces, and broader metadata-as-code approaches all share a common thread. Machine-readable knowledge wants to be plain text in a standard shape.

The open-standards argument from the early web is replaying here for agents. A knowledge format becomes valuable through adoption, not ownership. If this succeeds, the curated knowledge about your business becomes portable across every model and every cloud. The question of who controls the agent's mind gets a much more distributed answer.

But this is a zero point one specification. Conformance criteria, the reserved-filename registry, the rules on cross-links, and the citation system are all still being settled in the text. Anyone building on it today is building on a draft. The governance of who decides what this format becomes is not yet separate from Google Cloud, despite the open license. Treat it as a promising tool for sovereignty, but read the fine print on the version number.
