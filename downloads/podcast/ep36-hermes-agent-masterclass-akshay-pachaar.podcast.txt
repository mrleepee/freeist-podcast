In this episode you'll learn three things: how Hermes Agent's persistent memory keeps your workflow alive across sessions, the way its self-evolving skill system and background curator work, and how you can run multiple isolated agents with custom personalities and a built-in scheduler.  

In just two months, Hermes Agent has amassed over ninety thousand GitHub stars, a feat that signals a real shift in how developers think about personal eh! eye! helpers. The problem most agents share is that they wipe the slate clean when a session ends—your coding preferences, project conventions, the quick fix you found yesterday, all gone. Hermes Agent flips that problem on its head with a learning loop that remembers across sessions, writes its own reusable skills, prunes them in the background, and validates them offline through a pipeline called Gepa.  

The architecture is split into three clear layers. The Knowledge Layer is the persistent memory, built around two markdown files that sit at the core of every session: memory dot md, which can hold up to two thousand two hundred characters of environment notes, project conventions, and lessons learned, and user dot md, a one thousand three hundred seventy-five character snapshot of the user's profile and preferences. Both are injected into the system prompt at the start of each session. When these files approach about eighty percent capacity, the agent automatically consolidates the entries, merging similar notes to free up space. Beneath that sits a second tier of SQLite-backed conversation storage with full-text search—unlimited capacity but you have to actively query it. A third, optional tier can pull in external memory providers such as Mem0, prefetching relevant recollections before each turn.  

At the very top sits soul dot md, the identity layer. It's a single file that defines personality, tone, communication style, and any hard limits you want to impose. Because it's the first thing inserted into the system prompt, everything the agent learns is filtered through this defined persona.  

Skills themselves are markdown files with YAML frontmatter, acting as procedural memory rather than static knowledge. They expose three levels of disclosure: level zero shows only names and descriptions, roughly three thousand tokens, level one loads the full content when needed, and level two drills into reference files for deep context. The agent creates new skills autonomously whenever it completes a complex task, stumbles onto a working solution after an error, receives a correction, or discovers a non-trivial workflow.  

A background system called the Curator runs after seven days of inactivity. In its first phase it makes deterministic transitions—skills untouched for thirty days become stale, and those left for ninety days are archived. The second phase forks a language model to review each skill, deciding whether to keep, patch, consolidate, or archive it. Crucially, the Curator never touches bundled or hub-installed skills, never auto-deletes anything, and takes a snapshot before every pass.  

If you need more than one agent, Hermes lets you create profiles—fully isolated instances with separate configuration, memory, skills, sessions, and even their own soul dot md. You can set up a programmer profile that delegates tasks to Claude Code, a designer that generates illustrations based on your style references, or a researcher that pulls a daily eh! eye! and machine-learning digest from trending GitHub repos, big-tech announcements, research papers, and social chatter, then delivers it straight to Telegram at a time you specify. The built-in cron scheduler understands jobs described in plain English, so you don't need to fiddle with cron syntax.  

Behind the scenes, Gepa, Genetic-Pareto Prompt Evolution, optimises the agent's prompts offline. Rather than asking the agent if it performed well, Gepa reads execution traces to see why things went wrong, then proposes improvements through evolutionary search. It generates evaluation datasets, runs the optimizer, scores candidates with an em! em! as judge, and enforces strict gates: every candidate must pass all tests, stay under fifteen kilobytes, and preserve caching. The best variant is then issued as a pull request. Each run costs roughly two to ten dollars and needs no jee! pee! you!.
