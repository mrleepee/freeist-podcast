Imagina que cada vez que hablas con Claude, tienes que explicarle todo desde el начала. Tu nombre, tus preferencias, cómo te gusta trabajar... Eso suena agotador, ¿verdad? Bueno, Anthropic pensó lo mismo. Por eso creó algo llamado Skills, y hoy te voy a explicar cómo funcionan. En este episodio vas a aprender qué son los Skills, cómo crearlos paso a paso y cómo compartirlos con otros.

Un Skill es básicamente una carpeta especial que contiene un archivo llamado SKILL.md. Este archivo tiene instrucciones escritas en un formato llamado Markdown, con información adicional en YAML en la parte superior. Dentro de esa carpeta puedes tener subcarpetas opcionales: una para scripts con código ejecutable, otra para referencias con documentación, y otra para recursos como plantillas. Lo más importante es que el archivo principal debe llamarse exactamente SKILL.md, con esa escritura exacta, sin cambios. Si escribes skill.md o Skill.md, no va a funcionar. Y los nombres de las carpetas usan un estilo llamado kebab-case, que significa palabras separadas por guiones, como crear-presentaciones o gestionar-tareas.

Ahora, ¿por qué son útiles los Skills? Porque te permiten enseñarle a Claude una vez y beneficiarte siempre. En lugar de explicar tus procesos y preferencias en cada conversación, el Skill guarda ese conocimiento. Imagina que trabajas con un proyecto de software. Cada vez que inicias una sesión, Claude ya sabe qué herramientas usas, qué formato sigue tu código, qué convenciones sigues. Eso es un ahorro enorme de tiempo.

El equipo de Anthropic estableció tres principios básicos para diseñar Skills. El primero se llama revelación progresiva. Funciona en tres niveles. El YAML en la parte superior del archivo siempre se carga en el prompt del sistema de Claude, para que él sepa cuándo el Skill puede ser relevante. El cuerpo del SKILL.md se carga solo cuando Claude cree que el Skill aplica. Y los archivos en las carpetas de referencias y recursos se descubren solo cuando se necesitan. Este sistema reduce el uso de tokens mientras mantiene experiencia especializada.

El segundo principio es la composabilidad. Claude puede cargar varios Skills al mismo tiempo. Tu Skill debe funcionar junto con otros sin conflictos. Piensa en bloques de construcción que puedes combinar como quieras.

El tercer principio es la portabilidad. Los Skills funcionan igual en Claude.ai, en Claude Code y en la API, sin cambios. No importa dónde los uses, hacen lo mismo.

Si ya conoces MCP, que es el Protocolo de Contexto de Modelo, los Skills añaden una capa de conocimiento encima. La guía usa una analogía de cocina. MCP proporciona la cocina profesional con herramientas e ingredientes. Los Skills proporcionan las recetas con instrucciones paso a paso. Sin Skills, puedes conectar un servidor MCP pero no saber qué hacer después. Con Skills, flujos de trabajo preconstruidos se activan automáticamente.

Antes de escribir código, necesitas una fase de planificación. Empieza con dos o tres casos de uso concretos. Para cada uno, define qué activa el Skill, qué flujo de trabajo de múltiples pasos permite, qué herramientas necesita y qué conocimiento del dominio debe incluir. La guía identifica tres categorías comunes de Skills. La primera es creación de documentos y recursos, para producir resultados consistentes y de alta calidad como presentaciones, hojas de cálculo o diseños. La segunda es automatización de flujos de trabajo para procesos de múltiples pasos que se benefician de una metodología constante. La tercera es mejora de MCP, proporcionando guía de flujo de trabajo que convierte el acceso crudo a herramientas en flujos confiables y optimizados.

Los requisitos técnicos son sencillos. El YAML en la parte superior es lo más importante porque determina cuándo Claude carga el Skill. Necesitas un campo de nombre en kebab-case y un campo de descripción con menos de 1024 caracteres. La descripción debe incluir qué hace el Skill, cuándo usarlo y frases específicas que los usuarios podrían decir. Por seguridad, no puedes usar corchetes angulares XML ni reservar nombres que contengan claude o anthropic.

Una buena descripción sigue un patrón: qué hace, cuándo usarlo y capacidades clave. Debe ser específica y accionable con frases como usa esto cuando el usuario menciona sprint, tareas de Linear o planificación de proyecto. Una mala descripción es vaga, no tiene frases de activación o es demasiado técnica sin lenguaje claro para el usuario.

Para escribir instrucciones efectivas, sé específico y accionable. Incluye manejo de errores, referencia los recursos incluidos de forma clara y usa la revelación progresiva. Mantén el SKILL.md enfocado en instrucciones centrales y mueve la documentación detallada a la carpeta de referencias. La estructura recomendada incluye pasos numerados con resultados esperados, ejemplos de escenarios comunes y una sección de solución de problemas.

Para probar e iterar, la guía recomienda tres niveles de rigor. La prueba manual en Claude.ai es rápida para iterar. La prueba escrita en Claude Code permite validación repetible. Y la prueba programática vía la API de Skills permite evaluación sistemática. El enfoque más efectivo es iterar en una tarea difícil hasta que Claude tenga éxito, luego extraer ese enfoque ganador al Skill.

Tres áreas de prueba son críticas. Las pruebas de activación aseguran que el Skill se carga en los momentos correctos y no para preguntas no relacionadas. Las pruebas funcionales verifican que las salidas son correctas y el manejo de errores funciona. Y la comparación de rendimiento prueba que el Skill mejora los resultados versus una línea base sin el Skill.

Después de encontrar casos límite o fallos, la guía recomienda llevar esos ejemplos al skill-creator para mejora iterativa. Las señales a vigilar incluyen subactivación cuando el Skill no carga cuando debería, sobreactivación cuando carga para consultas irrelevantes, y problemas de ejecución con resultados inconsistentes o fallos en llamadas API.

Cinco patrones clave emergieron de los primeros usuarios. El primero es orquestación de flujo de trabajo secuencial para procesos de múltiples pasos en un orden específico, con ordenamiento explícito de pasos, dependencias entre etapas, validación en cada punto e instrucciones de reversión. El segundo es coordinación multi-MCP para flujos de trabajo que abarcan varios servicios, con separación clara de fases y paso de datos entre MCPs. El tercero es refinamiento iterativo para calidad de salida que mejora con iteración, usando criterios explícitos de calidad y scripts de validación. El cuarto es selección de herramientas consciente del contexto donde el mismo resultado usa diferentes herramientas dependiendo del contexto, con criterios claros de decisión y opciones de respaldo. El quinto es inteligencia específica de dominio que añade conocimiento especializado más allá del acceso a herramientas, embeddings de experiencia de dominio y verificaciones de cumplimiento.

Para distribución y compartir, los Skills son un estándar abierto diseñado para ser portable entre plataformas de IA, similar a MCP. Los usuarios individuales descargan carpetas de Skills, las comprimen y las suben desde la configuración de Claude.ai. Los administradores de organizaciones pueden implementar Skills para todo el espacio de trabajo. Para uso programático, la API proporciona un endpoint de Skills para listar y gestionar Skills, añadiéndolos a mensajes mediante el parámetro container.skills, y control de versiones a través de la Consola de Claude. Los Skills en la API requieren la beta de la Herramienta de Ejecución de Código. El enfoque recomendado de distribución es alojar en GitHub con un repositorio público, README claro y ejemplo de uso, luego documentar el Skill junto con cualquier integración de MCP.

La solución de problemas cubre problemas comunes. Los Skills que no se cargan típicamente tienen nombres incorrectos de SKILL.md o YAML frontmatter inválido. Los Skills que no activan necesitan descripciones revisadas con frases específicas de activación. Los Skills que activan demasiado necesitan activadores negativos y alcance más específico. Los problemas de conexión de MCP requieren verificar el estado del servidor, autenticación y nombres correctos de herramientas. Las instrucciones que no se siguen suelen ser causadas por instrucciones largas, puntos críticos ocultos o lenguaje ambiguo. La guía recomienda usar scripts para validaciones críticas ya que el código es determinista mientras la interpretación de lenguaje no lo es.

El proceso completo desde la planificación hasta un Skill funcionando puede lograrse en quince a treinta minutos usando la herramienta skill-creator. Esta guía representa la visión de Anthropic para hacer la personalización de IA accesible y estandarizada, permitiendo a desarrolladores y usuarios avanzados construir flujos de trabajo confiables y repetibles que transforman a Claude de un asistente de propósito general en un colaborador especializado adaptado a dominios y tareas específicas.

Lo que realmente me llama la atención de todo esto es cómo los Skills convierten a Claude en algo verdaderamente tuyo. No es solo un asistente genérico que responde lo que puede. Es una extensión de cómo tú trabajas, piensas y creas. Y eso, creo yo, cambia completamente la relación que tenemos con la inteligencia artificial.
