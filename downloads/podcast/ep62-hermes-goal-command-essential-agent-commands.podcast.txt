The Goal command is the most significant productivity feature in Hermes Agent's latest release. It gives Hermes a persistent objective that survives across multiple turns. Here is how it works. After every turn, a lightweight judge model checks whether the goal has been satisfied by the agent's last response. If the goal is not yet achieved, Hermes automatically feeds a continuation prompt back into the same session and keeps working. This loop continues until the goal is achieved, you pause or clear it, or the turn budget runs out. The command is inspired by the Ralph loop pattern and directly influenced by Codex see! el! eye!'s own goal feature by Eric Traut at Open eh! eye!. The core idea is simple but powerful: keep a goal alive across turns and do not stop until it is achieved.

Consider when you would use this. You have a messy codebase with failing tests scattered across a directory. Normally, you would fix one test, see if it passes, fix the next one, and repeat. With the Goal command, you simply type forward slash goal Fix every failing test in tests slash hermes underscore see! el! eye! slash and make sure scripts slash run underscore tests dot ess! h! passes. Hermes then works through the entire task autonomously, looping turn after turn until every test passes. The syntax is straightforward. Forward slash goal followed by your goal text sets the standing objective and kicks off the first turn immediately. You do not need to send a separate message. Forward slash goal status shows the current goal and turns used. Forward slash goal pause stops the auto-continuation loop without clearing the goal. Forward slash goal resume restarts the loop and resets the turn counter. And forward slash goal clear drops the goal entirely.

There is also a powerful subgoal feature. While a goal is active, you can append extra acceptance criteria using forward slash subgoal without resetting the loop. For example, if you started with fixing tests and halfway through realise you also want a regression test added, you type forward slash subgoal add a regression test for the bug you just patched. The judge then requires both the original goal and all subgoals to be met before marking the task as done.

How does the judge actually work? After every turn, Hermes calls an auxiliary model with the standing goal text and the agent's most recent response. The judge is deliberately conservative. It only marks a goal as done when the response explicitly confirms completion, when the final deliverable is clearly produced, or when the goal is unachievable. If the judge encounters an error, Hermes defaults to continuing rather than stopping. A broken judge never blocks progress. The turn budget, defaulting to twenty turns, serves as the real safety net. The judge model can be configured. By default it uses your main model, but you can route it to a cheaper, faster model like Google Gemini Flash to keep costs down, since the judge call is small at around two hundred output tokens and runs only once per turn.

Goal state is persisted in Hermes's session database, meaning you can set a goal, close your laptop, come back the next day, resume the session, and the goal is still there exactly as you left it. The continuation prompt is a plain user role message that does not mutate the system prompt or invalidate prompt caching, so a twenty turn goal costs the same cache wise as twenty turns of normal conversation.

Beyond the Goal command, power users are relying on a suite of slash commands that make Hermes dramatically more capable. Cron schedules Hermes to perform tasks automatically. Background sends Hermes off to work on a longer task while you keep chatting in the foreground. Research, processing documents, summarising saved articles, or anything that takes a few minutes but does not need you staring at it. Queue lets you add the next instruction without interrupting what Hermes is currently doing. It is one of the easiest ways to stop derailing your own agent.
