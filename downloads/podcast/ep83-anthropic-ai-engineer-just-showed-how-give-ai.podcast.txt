Imagine asking an A.I. assistant to help you with a project one day, putting in all the context and background, and then the next time you open a new session, it's as if none of that conversation ever happened. That's been the reality of AI agents until now, and it's a surprisingly fundamental limitation given how much we expect these systems to do.

Anthropic has just unveiled a memory architecture that changes everything. At its core, the system solves a problem that has plagued AI agents since their inception: isolation. Previous agents couldn't transfer knowledge between sessions, meaning every conversation started from scratch. This new approach gives agents something they never had before: a persistent memory that spans across time and sessions.

The first layer is called Memory Stores, and it's essentially a file system that attaches to each session. Think of it as a shared workspace where agents can read and write information, and crucially, access that information in future sessions. These stores can be created per user, per workspace, or even per organisation, giving developers real flexibility. They support versioning, so you can track how information changes over time, and sessions can be given read-only or read-write access depending on what you need. There's even a user interface for manually inspecting and editing memory files, which is rather handy for debugging.

But here's where it gets really interesting. There's a process called Dreaming, which sounds rather whimsical but is actually quite profound. Dreaming runs as an asynchronous batch job in the background, using a multi-agent system with an orchestrator and subagents. What does it do? It reviews previous sessions and essentially tidies up the memory store. It fact-checks information, adds enrichment details like dates and identifiers, consolidates what it finds, and removes duplicates. It even organises files by creating index files so everything is easier to find later. Importantly, Dreaming is non-destructive. It clones the input to an output memory store, so nothing is lost in the process. You can track its progress through token count updates, and it offers full observability through the session details it creates.

In practical terms, Anthropic demonstrated creating memory stores via the command line and console, showed sessions with and without memory stores side by side, and ran dreaming jobs with configurable parameters like model choice and session IDs. The difference in information retrieval before and after dreaming was quite striking.

Now, is this expensive to run? The honest answer is yes, it's designed to be exhaustive, so it uses a significant number of tokens. However, they're expecting around a ninety-five percent cache hit rate on dream sessions, which helps considerably. They're also exploring lower-cost options like batch-style discounts, so this could become more accessible over time.

What Anthropic has built is essentially three composable layers: Sessions, which are the isolated instances of AI running; Memory Stores, which connect information across those sessions; and Dreaming, which continuously organises and enriches that memory over time. Together, they represent a fundamental shift in how AI agents can operate, moving from isolated one-off interactions to something that genuinely feels like a persistent, evolving memory. It's early days, but this approach could reshape what we expect from AI systems entirely.
