Imagina que construyes un robot pequeño. Funciona bien al principio. Después, agregas más piezas, más instrucciones, más funciones. Pasan los meses y el robot tiene tantas partes que ya no sabe qué hacer. Se mueve lento y comete muchos errores. Esto es exactamente lo que pasó con un programa de inteligencia artificial para manejar inventarios. Se llamaba Stock Pilot. Los ingenieros lo construyeron poco a poco durante mucho tiempo. El programa tenía un sistema de instrucciones muy largo, más de cuatrocientas líneas. Tenía doce herramientas diferentes y varios subagentes trabajando juntos. Al principio, el programa tenía una precisión del ochenta y tres por ciento. Después de tantas modificaciones, la precisión cayó hasta el sesenta y dos por ciento. Eso es una baja muy grande.

¿Por qué pasó esto? Los expertos encontraron varias razones. Primero, el programa tenía demasiadas instrucciones mezcladas. Algunas instrucciones se contradecían entre sí y el programa no sabía qué seguir. Segundo, las herramientas no estaban bien diseñadas. Hacían trabajos que el programa podía hacer solo con funciones básicas. Tercero, los subagentes no se comunicaban bien con el sistema principal. Se enviaban mensajes confusos. Cuarto, el programa recibía mucha información innecesaria que confundía sus decisiones. Todo esto junto creó un sistema muy difícil de manejar y mejorar.

Los ingenieros desarrollaron un método para resolver el problema. Lo llamaron Hill Climbing, que significa subir la colina en inglés. El proceso era simple pero efectivo. Primero, crearon pruebas llamadas EVALs para medir el rendimiento real del programa. Segundo, analizaron los errores específicos que el programa cometía. Tercero, hicieron pequeños cambios en el diseño y repitieron las pruebas. Cuarto, transfirieron algunas tareas técnicas a una plataforma llamada Claude Managed Agents. Esta plataforma ayuda con el trabajo pesado de infraestructura.

Los cambios más importantes fueron tres. El primer cambio fue crear Skills en lugar de tener instrucciones enormes. Skills son bloques pequeños de información que el programa usa cuando los necesita. Es como tener libros organizados en lugar de tener todo en una sola página enorme. El segundo cambio fue usar operaciones básicas en lugar de herramientas especiales. Por ejemplo, el programa ahora usa búsqueda en internet, ejecución de código y navegación de archivos. Estas operaciones son como herramientas universales que el programa ya sabe usar. El tercer cambio fue simplificar. Redujeron las doce herramientas a solo las funciones fundamentales que el programa tiene disponibles siempre.

Para probar todo esto, los ingenieros crearon un sistema de evaluación muy completo. Usaron pruebas de regresión para tareas simples de un solo paso. También usaron pruebas de modos de falla para situaciones complejas con múltiples pasos. Los evaluadores midieron cosas concretas como tiempo de respuesta, número de tokens y cantidad de pasos. Además, usaron otro programa de inteligencia artificial para juzgar la calidad del tono, el estilo y la calidad general de las respuestas.

El taller mostró cómo usar Claude Code para analizar los errores de las pruebas. El programa identifica patrones en los fallos y sugiere cambios específicos en la arquitectura del sistema. Es una forma muy práctica de modernizar agentes complejos sin perder las capacidades que ya funcionan.

La lección más importante de todo esto es bastante simple. Cuando construyes sistemas de inteligencia artificial, menos es más. Empieza con funciones básicas y agrega complejidad solo cuando es necesario. Un sistema simple es más fácil de mejorar, más rápido y más confiable. Si agregas demasiado desde el principio, después es muy difícil limpiar el desorden. Los mejores agentes son los que saben hacer mucho con poco.
